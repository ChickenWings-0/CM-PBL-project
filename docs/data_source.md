# Data Sources

The project uses three tiers of data (see `PLAN.md` section 2). This file explains exactly where each dataset comes
from and how it was made, so anyone can reproduce it.

## Tier A: verification functions

These are simple mathematical functions whose answers are known by hand. They are built directly into `src/tests.c`
and need no data file.

| Function | Used in | Known answer |
|---|---|---|
| y = 2x + 1 | T1 (linear interpolation) | y(2.5) = 6 |
| y = x³ − 2x² + x − 5 | T2, T3 (local cubic) | exact for any x, because the method is a cubic |
| sin x on [0, π] | T4 (trapezoidal) | integral = 2 |
| x³ on [0, 2] | T5, T6 (Simpson rules) | integral = 4 |
| x² on [0, 5] with 5 intervals | T14 (Simpson fallback) | 64/3 + 20.5 = 41.8333 |
| x² − 2 = 0 on [1, 2] | T7–T9 (root finding) | √2 = 1.41421356… |

## Tier B: synthetic Delhi household (`data/synthetic_day.csv`)

**Generated by the C program itself.** The function `generate_synthetic_csv()` in `src/load_model.c` creates the file.
If the file is missing it is created automatically on the next run, and it can also be regenerated from
**Menu 1 → 4**.

### The model

```
P(t) = 0.5 + 1.0·g(t; 8.0, 1.0) + 0.8·g(t; 15.0, 2.5) + 3.0·g(t; 20.5, 1.5)      [kW]
g(t; μ, σ) = exp( −(t − μ)² / (2σ²) )                                           (bell curve)
```

| Term | Meaning |
|---|---|
| 0.5 kW base | Fridge, fans, standby loads, always on |
| 1.0 kW bump at 08:00 (width σ = 1 h) | Morning: water pump, kettle, iron |
| 0.8 kW bump at 15:00 (width σ = 2.5 h) | Afternoon AC during the hottest hours |
| 3.0 kW bump at 20:30 (width σ = 1.5 h) | Evening peak: AC, lights, TV, cooking |

The shape was chosen to look like a summer day in a Delhi home with air-conditioning:
- low and flat at night
- a small morning peak
- a broad afternoon rise
- a high evening peak that goes above the 3 kW limit for about two hours

The parameters are *illustrative*, not fitted to measured Delhi data. The day's total is 30.69 kWh (about 920 kWh
per month), which is typical for a large home running AC.

### Exact answers (why this dataset is valuable)

- **Exact power** at any time: evaluate P(t).
- **Exact energy:**

  `E(a, b) = 0.5(b − a) + Σ A·σ·√(π/2)·[erf((b − μ)/(σ√2)) − erf((a − μ)/(σ√2))]`

  For the full day this gives 30.6881991914 kWh.
- **Exact crossing times** of 3 kW, and of the 15 kWh budget: solved with bisection to 10⁻¹² h on the exact formulas.

### How the CSV is made

1. Evaluate P(t) at t = 0, 1, 2, …, 24 h, giving 25 readings.
2. Round each reading to 4 decimal places (0.1 W), like a meter display.
3. Replace the readings at hours **4, 9, 13, 14 and 19** with `NA`, to simulate lost meter readings:
   - 04:00: night, flat load (easy case)
   - 09:00: just after the morning peak, where the curve is steep
   - 13:00 and 14:00: two lost readings in a row
   - 19:00: on the evening ramp, close to the 3 kW threshold (hardest case)

## Tier C: real household (UCI dataset)

### Citation

> Hebrail, G. & Berard, A. (2006). *Individual Household Electric Power Consumption* [Dataset].
> UCI Machine Learning Repository. https://doi.org/10.24432/C58K54

- **Licence:** Creative Commons Attribution 4.0 International (CC BY 4.0). Use is allowed with attribution, as given above.
- **Page:** https://archive.ics.uci.edu/dataset/235/individual+household+electric+power+consumption
- **Content:** 2,075,259 one-minute measurements from one house in Sceaux, France (7 km from Paris),
  December 2006 to November 2010.
- **Column used:** `Global_active_power`, the household's minute-averaged active power in kW. Missing values
  in the original file are marked `?`.

### Extraction steps (reproducible)

1. Download `individual+household+electric+power+consumption.zip` (about 20 MB) from the page above and unzip it.
   This gives `household_power_consumption.txt` (about 127 MB, separated by `;`).
2. Run the one-time preparation script from the project folder:
   ```
   python scripts/extract_uci_day.py path/to/household_power_consumption.txt
   ```
3. The script does the following:
   1. Reads the 1440 rows for **14/5/2007** plus the **00:00 row of 15/5/2007**, which is used as the 24:00 reading.
   2. Checks that no minute is missing (`?`). The script stops if the day is incomplete.
   3. Writes **`data/real_day_minute.csv`**: 1441 rows, time in decimal hours, power in kW.
   4. Takes the minute value at every whole hour (hh:00) as that hour's reading, an instantaneous sample, and writes
      **`data/real_day_hourly_complete.csv`** (25 rows). This is the ground truth.
   5. Writes **`data/real_day_hourly.csv`**: the same 25 rows with hours 4, 9, 13, 14 and 19 set to `NA`.
      This is the same lost-reading pattern as the synthetic dataset.
   6. Prints the metered energy of the day: **24.4630 kWh**.

### Why 14 May 2007?

- All 1440 minutes and the next midnight are present, so the reference values are complete.
- The hourly readings cross 3 kW in the evening, so the threshold analysis has something to find.
- The 15 kWh budget is reached during the evening peak.
- The day was picked for these features after scanning the complete days in the file. It is an illustration,
  not a random sample.

### Reference values used for error analysis

| Quantity | How it is computed from the 1-minute file |
|---|---|
| Metered energy over [a, b] | Σ Pₖ × (1/60 h) over the minutes in [a, b) (each value is a 1-minute average) |
| True budget time | Cumulative energy grows linearly within each minute; find where it reaches 15 kWh |
| True power crossings | Every sign change of Pₖ − 3 between consecutive minutes, with straight-line interpolation |
| True value of a hidden reading | `real_day_hourly_complete.csv` |

### Limitations of this data

- The house is in France, not India, so the appliance mix and climate differ. It is used because it is the cleanest
  freely available minute-level household dataset.
- An Indian alternative is **iAWE** (Indian dataset for Ambient Water and Energy, IIIT-Delhi, 2013), which records
  a Delhi home. It is distributed in a format that needs extra tooling, so it is listed as a future enhancement.
